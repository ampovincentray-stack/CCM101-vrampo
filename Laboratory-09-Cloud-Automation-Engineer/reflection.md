# Mission Reflection

Laboratory Activity 9 allowed me to understand how cloud management can be simplified and accelerated by automation. Managing several hundreds of servers without automation would mean spending much time and effort. However, there are possibilities to automate the repetitive processes using Bash commands and ‘Cron’ jobs. Doing so reduces manual work and eliminates risks of human error.

I have to mention that automation can be risky in the event of a flaw in a script. For example, in case a malicious command is included in a script that needs to be executed on 1,000 servers, many computers might lose important data or get their systems disabled. This is why evaluation of scripts is necessary before they can be executed.

The process of writing a Bash script differed in comparison to creating a Docker Compose YAML file during Mission 6. With Bash scripting, commands as well as variables are employed, thus enabling step by step execution of the desired process. On the other hand, Docker Compose is based on YAML language, which is used to describe the various application services, settings and available resources. Although both techniques are useful in terms of automation, each one addresses a different task.

Recapping what I learned from Lab 1 to Lab 9, I had the chance to comprehend how cloud computing can be viewed from more than just the aspect of running applications over the cloud. Indeed, it also implies the aspects of managing resources, protecting information, maintaining services, and employing automation.

My favorite position was that of Cloud Automation Engineer because I had the opportunity to write a script that would perform tasks on its own on a repetitive basis. The fact that I could see my backup created after running the script was very enlightening in terms of having an understanding of how important automation is.
